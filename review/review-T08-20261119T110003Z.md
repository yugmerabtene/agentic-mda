## Risques résiduels et limites

- La corrélation repose sur une recherche par mot-clé NVD (`keywordSearch`) sans CPE exact dans la requête API ; certaines correspondances restent approximatives (confiance "medium" au plus). Une validation par CPE (`cpeName`) réduirait les faux positifs.
- Le cache NVD (TTL 24 h) peut renvoyer des données obsolètes si le NVD met à jour une fiche entre-temps.
- Aucun CVE n'est marqué KEV (`kev: false` partout) ; la priorisation par exploitation connue n'est pas disponible sans clé API NVD / CISA KEV.
- Les tests unitaires mockent le réseau ; aucun test d'intégration contre le NVD réel n'est automatisé (l'exécution réelle a été faite via le cache disque, sans appel réseau neuf lors de cette re-revue).
- Le champ `confidence_motif` est conservé en sortie (correction F-005 de la revue précédente appliquée).
